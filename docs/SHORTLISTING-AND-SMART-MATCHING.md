# الترشيحات والنظام الذكي للترشيح — مستند تطوير

> مبنيّ على فحص الكود الفعلي في `main` (لا على تخمين). كل «موجود» تحقّقتُ منه، وكل «ناقص» غيابُه مؤكَّد.

---

## 1. الحالة القائمة (ما هو مبنيّ فعلًا)

### البيانات
- `campaign_shortlists` → `campaign_shortlist_versions` → `campaign_shortlist_items`
  إصدارات مؤرّخة: كل تعديل بعد الإرسال يُنشئ إصدارًا جديدًا ينسخ العناصر ويحفظ التاريخ.
- على كل عنصر: `match_score` (0–100) و`reasons` (JSON) و`client_decision` (pending/approved/rejected) و`decision_reason`.

### الخدمة `ShortlistService`
`getOrCreate` · `matchScore` · `addCreator` (أساسي/احتياطي) · `submit` · `newRevision` · `clientDecision` · إشعارات القرار.

### المُطابِق الحالي `matchScore(campaign, creator)`
| الإشارة | النقاط |
|---|---|
| المنصّة مطابقة (من مخرجات الحملة) | +40 |
| متابعون ≥ 500k / ≥ 100k / أقل | +25 / +15 / +8 |
| موثّق (موثوق) | +20 |
| سعر محدّد | +10 |
| نشط | +5 |

قاعدة أساسية بسيطة، تُعيد درجة + أسبابًا تُعرض للمستخدم.

---

## 2. عيوب المُطابِق الحالي (مؤكَّدة بالقراءة)

1. **«المنصّة مطابقة» تُمنح للجميع حين لا مخرجات بعد.**
   `$platforms->isEmpty() || contains(...)` — والحملة تُنشأ قبل مخرجاتها، فيحصل كل مبدع على +40 بلا سبب. الدرجة مضلّلة في أهمّ لحظة (بداية الترشيح).
2. **يقرأ `primary_platform` فقط** ويتجاهل `creator_platforms` (المبدع متعدّد المنصّات ومتابعوه موزّعون).
3. **لا يستخدم التصنيفات** (`content_categories` / `creator_categories`) رغم أنها جوهر الملاءمة.
4. **لا ملاءمة ميزانية:** سعر المبدع مقابل ميزانية الحملة/المخرَج غير محسوب.
5. **لا أداء تاريخي:** التزام المبدع وإكماله السابق (من `collaborations`/`content_items`) مُهمَل.
6. **لا قواعد استبعاد:** تعارض علامات، مبدع مشغول بحملة نشطة، فئات محظورة.
7. **المتابعون ليسوا تفاعلًا:** لا حقل engagement — والوصول بلا تفاعل إشارة ضعيفة.

---

## 3. الجزء الأول: دمج الترشيحات في النظام (بلا ذكاء بعد)

الهدف: الترشيح ليس صفحة منعزلة بل حلقة في سلسلة التشغيل، بياناتها تنتقل تلقائيًّا.

### 3.1 الحملة ← الترشيح (تلقائي)
- الحملة تعرف **منصّاتها وتصنيفاتها وميزانيتها** كحقول أولى لا كنصّ في الموجز.
  **مطلوب:** جدول/أعمدة `campaign_targeting` (platforms[], categories[], min/max_followers, audience_geo, audience_gender) تُملأ من موجز الطلب عند التحويل — فلا يُعاد إدخالها.
- المُطابِق يقرأ منها بدل تخمينها من المخرجات.

### 3.2 الترشيح ← التعاون (بلا سجل مكرّر)
- عند اعتماد العميل لعنصر ترشيح: زرّ **«حوّل إلى تعاون»** يُنشئ `collaboration` مرتبطًا بـ`shortlist_item_id` و`creator_id` و`campaign_id`، وينقل الأجر المقترَح.
- **منع التكرار:** إن وُجد تعاون لنفس (المبدع، الحملة) يُفتح الموجود لا يُنشأ ثانٍ.

### 3.3 روابط ثنائية الاتجاه
- صفحة الترشيح تربط: الحملة · العميل · العلامة · المخرجات.
- صفحة المبدع تُظهر: «مُرشَّح في N حملة» مع الحالات.
- عنصر الترشيح المعتمَد يربط تعاونه الناتج.

### 3.4 الحالات والإعلان (مبنيّ جزئيًّا)
- إعلان الانتظار موجود (`WaitingOn`): «الدور على العميل — بانتظار القرار».
- **مطلوب:** بطاقة «الخطوة التالية» على الحملة تتغيّر بحسب حالة الترشيح (أضِف مرشّحين / أرسل للعميل / بانتظار القرار / حوّل المعتمَد).

### 3.5 الصلاحيات والعزل (قائم — يُحترَم)
- الوكالة تُرشّح وترسل؛ العميل يقرّر من بوابته؛ عزل المستأجر مغلق افتراضيًّا. لا يُوسَّع.

## 4. الجزء الثاني: النظام الذكي للترشيح

مبدأ حاكم: **لا نُلفّق ذكاءً.** كل درجة تُشتقّ من بيانات حقيقية موجودة، وما يحتاج مصدرًا خارجيًّا (ديموغرافيا الجمهور، تفاعل حقيقي) يُبنى خلفه **مُحوِّل (adapter) + بديل صادق**، ويُعلَن أنه «تقديري» حتى يُربَط المصدر.

### 4.1 محرّك التسجيل متعدّد الأبعاد
درجة مركّبة موزونة، كل بُعد 0–100، والوزن قابل للضبط:

| البُعد | المصدر (موجود؟) | الوزن المقترَح |
|---|---|---|
| ملاءمة المنصّة | `creator_platforms` مقابل `campaign_targeting` | 20٪ |
| ملاءمة التصنيف/المجال | `content_categories` مقابل تصنيفات الحملة | 20٪ |
| ملاءمة الجمهور (حجم) | `followers_count` مقابل نطاق الحملة | 10٪ |
| **التفاعل** | ⚠️ غير موجود — يحتاج API أو إدخال | 15٪ (تقديري حتى يُربَط) |
| ملاءمة الميزانية | `rate_per_post_minor`/`base_rate_minor` مقابل ميزانية المخرَج | 10٪ |
| الأداء التاريخي | `collaborations` (إكمال/التزام) + `content_items` (تسليم في الموعد) | 15٪ |
| الموثوقية | `mowthooq_status = verified` + التحقّق المالي | 10٪ |

المخرَج: `score` + `breakdown[]` (كل بُعد ودرجته وسببه) + `flags[]` (تحذيرات).

### 4.2 قواعد الاستبعاد الصلبة (قبل التسجيل)
تُقصي المبدع تمامًا مع سبب واضح — لا تخفضه:
- حالة المبدع ليست `active`.
- تعارض علامة (المبدع مرتبط بمنافس — يحتاج جدول `brand_conflicts`).
- مشغول بحملة نشطة متداخلة التواريخ (اختياري، قابل للتجاوز).
- قدرة الحملة المطلوبة غير مفعّلة لدى المبدع (`creator_capabilities`).

### 4.3 الأداء التاريخي (يُبنى من الموجود)
`CreatorPerformance` مشتقّة، تُخزَّن مُجمَّعة (لا تُحسب كل مرّة):
- معدّل الإكمال = تعاونات مكتملة / إجمالي.
- الالتزام بالموعد = محتوى سُلّم قبل الاستحقاق / إجمالي.
- متوسّط أجر فعليّ.
- عدد التعاونات (خبرة).
تُحدَّث بحدث عند تغيّر حالة تعاون/محتوى.

### 4.4 الشفافية (إلزامية)
- كل درجة **قابلة للتفسير**: تُعرض تفكيكها وأسبابها، لا رقم غامض.
- الأبعاد التقديرية (التفاعل قبل ربط API) تُوسَم «تقديري» صراحةً.
- **لا قرار آليّ:** النظام يُرتّب ويقترح، والوكالة تختار. التوصية مساعِدة لا حاكمة.

### 4.5 التوصية (الطبقة العليا)
- «أفضل N مرشّح لهذه الحملة» = المرشّحون بعد الاستبعاد، مرتّبون بالدرجة المركّبة.
- زرّ **«اقترح مرشّحين»** يملأ المسوّدة تلقائيًّا (قابلة للتعديل) بأعلى N ضمن الميزانية.
- «لماذا هذا المبدع؟» يفتح التفكيك.

### 4.6 مسار الذكاء المتقدّم (بعائق خارجي موثّق)
لا يُبنى الآن، لكن تُترَك له الواجهة:
- **مطابقة دلالية بين موجز الحملة وملفّ المبدع** (embeddings) — يحتاج مزوّد نماذج. يُبنى `SemanticMatcher` بواجهة + بديل يُرجع 0، ويُعلَن معطّلًا حتى تُوفَّر المفاتيح.
- **ديموغرافيا الجمهور الحقيقية** (عمر/جغرافيا/جنس المتابعين) — تحتاج APIs المنصّات (Snapchat/TikTok/Instagram). تُبنى `AudienceProvider` (Fake الآن)، والبُعد يبقى «تقديري».

## 5. نموذج البيانات المطلوب

| جدول/عمود جديد | الغرض |
|---|---|
| `campaign_targeting` (أو أعمدة على `campaigns`) | منصّات/تصنيفات/نطاق متابعين/جمهور مستهدف — تُملأ من الموجز |
| `creator_performance` (مُجمَّعة) | إكمال/التزام/خبرة — مشتقّة، مُحدَّثة بحدث |
| `creator_engagement` | معدّل تفاعل لكل منصّة (يدوي الآن، API لاحقًا) |
| `brand_conflicts` | تعارض المبدع مع علامات منافسة |
| توسعة `campaign_shortlist_items` | حفظ `breakdown` (JSON) بجانب `match_score` |

كل المبالغ وحدات صغرى صحيحة. كل جدول معزول بالمستأجر (fail-closed).

---

## 6. خطة التنفيذ (مراحل، كل مرحلة مُختبَرة من الواجهة)

1. **إصلاح المُطابِق الحالي** (عيب المنصّة الفارغة + قراءة `creator_platforms` + التصنيفات). مكسب فوري بلا جداول جديدة.
2. **`campaign_targeting`** يُملأ من الموجز عند التحويل — أساس كل ملاءمة لاحقة.
3. **قواعد الاستبعاد** + عرض سبب الإقصاء.
4. **`creator_performance`** المشتقّة + بُعد الأداء.
5. **ملاءمة الميزانية** + وسم التقديري.
6. **التوصية «اقترح مرشّحين»** + تفكيك «لماذا».
7. **دمج الترشيح ← التعاون** بلا تكرار + الروابط الثنائية.
8. **المحوّلات المستقبلية** (Semantic/Audience) بواجهة وبديل، معطّلة بعائق موثّق.

---

## 7. معايير القبول

- الترشيح يبدأ بمرشّحين مقترحين حقيقيين مرتّبين بدرجة **قابلة للتفسير** لا برقم غامض.
- المُطابِق لا يمنح إشارة كاذبة (لا +40 للجميع).
- الاستبعاد يُعلَن بسببه، لا يُخفى المبدع بلا تفسير.
- تحويل المعتمَد إلى تعاون بلا سجل مكرّر، والبيانات تنتقل تلقائيًّا.
- الأبعاد التقديرية مَوسومة صراحةً؛ لا يُدّعى تفاعل أو ديموغرافيا لا نملكها.
- عزل المستأجر والصلاحيات محفوظة، مع اختبارات من البداية للنهاية.
- لا قرار آليّ: النظام يقترح، والإنسان يقرّر.

---

## 8. ما لا يُنفَّذ الآن (عوائق خارجية موثّقة)

- **ديموغرافيا الجمهور الحقيقية:** تحتاج اعتمادات APIs المنصّات. البُعد «تقديري» حتى تُربَط.
- **المطابقة الدلالية (AI):** تحتاج مزوّد نماذج. الواجهة جاهزة، والمنطق معطّل حتى تُوفَّر المفاتيح.
- **معدّل التفاعل الحيّ:** يدويّ الآن؛ يُؤتمَت مع ربط المنصّات.
